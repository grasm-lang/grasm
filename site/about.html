What this is, and what it is not.

Grasm is a systems language with an effect system, capability ceilings on packages, and tiered ownership without lifetime annotations. It is version 1.0.0, it has 650 libraries, and every one of them was written inside this repository.

Nothing here was invented

It is worth being direct about this, because a language site is the last place anyone expects to read it. Every idea in Grasm exists elsewhere, usually first and usually with more research behind it.

In GrasmWhere it came from
let / inout / own, value semantics, no lifetimes Hylo (formerly Val) has let/inout/sink. Swift has exclusivity, ARC and copy-on-write.
Effect rows, inferred and unified Koka — row-based effect types with inference. Also OCaml 5, Unison, Eff, Frank.
Capability ceiling per module Austral — capability-secure, no ambient I/O. Wyvern, and the E language before it.
Reference counting with copy-on-write Swift, Nim.
Generational references The slotmap pattern, in every entity-component system.
A reference interpreter as the specification WebAssembly does this, and does it better.

The closest single comparison is Hylo plus Koka, tied to a manifest the way Austral does it. What is uncommon is not the ideas but shipping them together with gates that prove the combination holds.

Who should not use this

Most people, today. Specifically:

  • If you need libraries. There are 650, all written here. Python has hundreds of thousands.
  • If you need speed. Rust and Zig are faster, and the numbers here say by how much.
  • If you need to hire. Nobody outside this repository has written Grasm.
  • If you need a native debugger. There is a Debug Adapter Protocol server, and it works against the interpreter. The Cranelift backend emits no DWARF, so GDB and LLDB cannot meaningfully inspect a compiled binary.
  • If you need async I/O. There are threads and structured concurrency, and no async/await.

Who might

Someone who genuinely models an untrusted dependency reaching the network or the filesystem as a threat, and who wants the compiler to enforce the boundary rather than a sandbox at run time. That is a real gap in Rust, Go, Zig and Python, and it is the one thing here that is not catching up to somebody else.

How it is built

249 normative clauses in 3548 lines of specification, under a hard ceiling — every addition since has been paid for by compressing prose already written. 167 clauses are stable and will not change incompatibly before 2.0; 26 are provisional and 60 are experimental. Version 1.0 promoted nothing: a clause moves when it passes the five-part test, one at a time, on its own evidence.

Every number on this site is computed from the repository when the site is written, or read from the last green gate run. None of them is a figure somebody remembered. If a gate has not run, the page says so rather than printing a number nobody measured.
