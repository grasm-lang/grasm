What a program may do
is written in its type.

Effects go in the signature. Capabilities go in the package manifest. Ownership is a tier you pick per value. It compiles ahead of time, runs in a browser, and four engines agree byte for byte on every program here.

The signature is the contract

A function’s type says what it returns and what it is allowed to do. The row is inferred from the body, so it cannot drift from the truth, and a caller that has not been given io cannot call something that performs it.

fn safe_div(a: i64, b: i64) -> i64 ! MathError {
    if b == 0 {
        fail(DivByZero)
    }
    a / b
}

fn report(n: i64) / {io} {        // this one prints; the type says so
    print("{n}")
}

! MathError is a failure the caller must handle. / {io} is an effect the caller must be permitted. Neither is a comment or a convention — both are checked.

A dependency cannot quietly grow teeth

This is the one thing here that other languages do not have. A library declares what it may reach. If a patch release starts reading your files, the build fails — in every consumer, without anybody reviewing the diff. Press the button: the verdicts are the ones scripts/security_bench.sh produces.

Four engines, one answer

The interpreter is normative. A bundle is that interpreter with the program attached. --native compiles ahead of time through Cranelift. A fourth build targets wasm32. Every gate here exists to hold them to the same answer.

What is different here

Effects, inferred

You do not write the row. The compiler works it out from the body and checks it against what you declared, so a function that starts touching the network stops compiling.

Capability ceilings

A package declares the effects it may perform. One that quietly starts reading files fails to build in every consumer — a compile error, not a code review.

Tiered ownership

No lifetime annotations. own and inout at the boundary, a region when a scope should own its allocations, a generational reference when a graph needs one.
