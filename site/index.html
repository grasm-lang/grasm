Code that can’t overstep.

Grasm is a systems language where a dependency cannot reach further than its manifest allows. Overstep, and it is a compile error.

Sneak one past the compiler.

A trusted math library ships a patch release. Same name, same signature, same result — and one new line that reads a file. This is the whole build.

The manifest is the ceiling

A package declares what it may reach. The compiler infers what it actually does — through every call, into every dependency — and refuses to build when the two disagree.

This is the reason the language exists. xz-utils, event-stream, SolarWinds: the attack is always the same shape, and the answer everywhere else is a runtime sandbox or a human reading the diff. Here it is a type error.

Three ideas. One language.

They were built to compose. Each one closes a hole the other two leave open.

Capabilities

A package states the effects it may perform. Exceeding it fails the build in every consumer — not in a review, not at run time.

Ownership in tiers

Value semantics by default, a region when a scope should own its allocations, a generational reference when a graph needs one. No lifetime annotations anywhere.

Four engines, one answer

Interpreter, bundle, ahead-of-time native, and wasm. Develop against instant feedback, ship a binary, run the same program in a browser.

Four engines. One answer.

The interpreter is normative. The other three have to match it, byte for byte, on every green build.

Effects live in the type.

You never write the row. The compiler infers it from the body and checks it against what you declared. Touch the network, and the function stops compiling — along with every caller that was not given the same permission.
