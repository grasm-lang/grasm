Systems language · v1.0.0

What a program may do is written in its type.

Effects go in the signature and are inferred from the body. Capabilities go in the package manifest and bound what a dependency can reach. Ownership is a tier you pick per value — no lifetime annotations.

Get started Syntax reference Run it in the browser

A signature is a contract

The row after / says what the function is permitted to do. You do not write it; the compiler works it out from the body and checks it against what you declared.

A dependency cannot quietly grow teeth

A trusted library ships a patch release that reads your files. Same name, same signature, same result. This is what happens:

app — grasm build

The ceiling is declared

A package states the effects it may perform. Exceeding it is a compile error in every consumer, not a code review.

Ownership in tiers

Value semantics by default, a region when a scope should own its allocations, a generational reference when a graph needs one.

Four engines, one answer

Interpreter, bundle, native and wasm. Every gate here exists to hold them to the same bytes.

Every program, every engine

The interpreter is normative. The other three have to match it, and the corpus is what proves they do.
