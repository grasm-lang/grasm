Concurrency

Tasks run in the order they were spawned, the block joins before the line after it, and the effect row crosses the boundary with them.

parallel and spawn

fn main() / {io, async} {
    var log = ""
    parallel {
        spawn { log += "a" }
        spawn { log += "b" }
    }
    print(log)          // "ab", every time, on every engine
}

The block records which spawn sites fired, in order, and the bodies run afterwards — which is what makes the order deterministic and the scope joined. A spawn body sees the enclosing scope rather than capturing it, which is the opposite of how a closure behaves and is documented as such.

Data-parallel methods

let doubled = xs.par_map(|v| v * 2)
let evens   = xs.par_filter(|v| v % 2 == 0)

Both preserve order, and both require the closure to be pure — which the effect system can prove rather than assume. A closure that prints will not typecheck here.

What is missing. There is no timer, channel or select library above these primitives yet. That is the async workstream on the roadmap.
