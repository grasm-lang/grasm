Playground

Grasm compiles to wasm32, so the language runs in a browser with no server behind it.

Running it locally

The wasm build and a host page live in the repository. Serve the directory and open it:

cargo build --release --target wasm32-unknown-unknown -p grasm_wasm
cp target/wasm32-unknown-unknown/release/grasm_wasm.wasm ProjectGold/web/grasm.wasm

python3 -m http.server -d ProjectGold/web

That page runs the corpus: pick a program, and it executes in the tab. Twelve of the programs under ProjectGold/ are browser applications built this way — a SPA router, a markdown editor, a collaborative todo list, a realtime analytics dashboard.

What the browser build can and cannot do

236 of the 275 corpus programs produce identical output in wasm. The other 39 are skipped for a reason the host cannot supply, and each names it: a filesystem, a socket, a process, threads, or a stack deep enough for the recursion limit the specification promises.

This page is not itself a playground yet. The wasm build works and the host page works; wiring an editor into this site is on the roadmap. Saying otherwise would be the kind of claim this project does not make.
